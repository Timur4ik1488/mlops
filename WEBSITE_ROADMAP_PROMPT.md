## 🟢 ШАГ 1. Введение в проблему AppSec и Математика Нейрона

### 1. 💡 Простыми словами
* **В чем боль реальной разработки?**  
  Обычные анализаторы кода (SAST) работают по регулярным выражениям: они ищут подстроки вроде `password = "..."` или `query("SELECT " + ...)`. Но 80–90% их находок — это мусор: тестовые пароли в `mock.ts`, плейсхолдеры из документации `"your_api_key"` или безопасные запросы с санитизацией. Разработчики устают от ложных тревог (**False Positives**) и отключают сканеры.
* **Как решает проблему нейросеть?**  
  В отличие от "тупой" регулярки, нейросеть способна оценивать **контекст**: откуда пришла переменная, кто её вызвал, проверены ли права доступа через Spring Security `@PreAuthorize`, похожа ли строка на настоящий ключ шифрования.
* **Почему нейросеть называется "Двухпоточной" (Dual-Branch)?**  
  Потому что человек-эксперт при аудите смотрит на две разные вещи:
  1. *Поток кода:* семантика инструкций (вызовы функций, операторы конкатенации).
  2. *Поток метаданных:* физические свойства (степень энтропии/случайности строки, имя файла, аннотации).  
  Мы создаем две параллельные нейросети и объединяем их выводы.

### 2. 📐 Глубокая математика
1. **Тензоры — язык нейросетей:**
   * Скаляр (0D): $s \in \mathbb{R}$ (например, число 42.0).
   * Вектор (1D): $v \in \mathbb{R}^D$ (например, вектор из 12 мета-признаков файла).
   * Матрица (2D): $M \in \mathbb{R}^{T \times D}$ (последовательность из $T$ токенов кода, где каждый токен — вектор размерности $D$).
   * Батч (3D): $B \in \mathbb{R}^{Batch \times T \times D}$ (пачка из нескольких методов кода для параллельного обучения).
2. **Формула базового слоя (Аффинное преобразование):**
   $$z = W \cdot x + b$$
   * $x \in \mathbb{R}^{d_{in}}$ — входные признаки.
   * $W \in \mathbb{R}^{d_{out} \times d_{in}}$ — матрица весов (веса определяют важность признаков).
   * $b \in \mathbb{R}^{d_{out}}$ — вектор смещения (bias, задает порог срабатывания).
3. **Пример расчета на числах:**  
   Пусть вход $x = [4.5, 32.0]$ (энтропия 4.5, длина строки 32).  
   Веса $W = [[0.8, 0.1]]$, смещение $b = [-3.0]$.  
   $$z = (0.8 \cdot 4.5) + (0.1 \cdot 32.0) - 3.0 = 3.6 + 3.2 - 3.0 = 3.8$$

### 3. 💻 Код на Python (PyTorch)
```python
import torch
import torch.nn as nn

# Создаем базовый искусственный нейрон для анализа подозрительной строки
class SimpleSecurityNeuron(nn.Module):
    def __init__(self):
        super().__init__()
        # Вход: 2 признака (энтропия, длина), Выход: 1 число (логит опасности)
        self.linear = nn.Linear(in_features=2, out_features=1)
        self.activation = nn.Sigmoid()

    def forward(self, x):
        # z = W * x + b
        raw_score = self.linear(x)
        # Превращаем в вероятность от 0.0 до 1.0
        probability = self.activation(raw_score)
        return probability

# Тестируем: строка с высокой энтропией 4.8 и длиной 40 символов
sample = torch.tensor([[4.8, 40.0]])
neuron = SimpleSecurityNeuron()
print(f"Вероятность того, что это боевой секрет: {neuron(sample).item():.4f}")
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Калькулятор одного нейрона".
* **Элементы:** Два ползунка $x_1$ (Энтропия от 0 до 8), $x_2$ (Длина строки от 0 до 100), ползунки весов $w_1, w_2$ и смещения $b$. 
* **Вывод:** Мгновенный расчет $z = w_1 x_1 + w_2 x_2 + b$ и вероятности $\sigma(z)$ с индикатором (Зеленый = Безопасно, Красный = Уязвимость).

### 5. 🧪 Тест и Практика
* **Вопрос 1:** Что произойдет с предсказанием линейного слоя, если все веса $W$ равны нулю?  
  *Варианты:* А) Ошибка деления на 0; Б) Выход будет строго равен вектору смещения $b$; В) Выход всегда равен 1.  
  *Ответ:* **Б**. При $W = 0$, $W \cdot x = 0$, следовательно $z = b$.
* **Задача:** Рассчитай вручную выход нейрона, если $x = [2.0, 1.0]$, $W = [[1.5, -2.0]]$, $b = [0.5]$.  
  *Решение:* $z = (1.5 \cdot 2.0) + (-2.0 \cdot 1.0) + 0.5 = 3.0 - 2.0 + 0.5 = 1.5$.

## 🟢 ШАГ 2. Функции активации, Нормализация и Регуляризация

### 1. 💡 Простыми словами
Если сложить 10 линейных формул $y = Wx + b$, получится ровно такая же прямая линия. Нейросеть не сможет понять сложные правила безопасности вроде: *«ЕСЛИ запрос конкатенируется, НО рядом есть плейсхолдер `?`, ТО это безопасно»*.
* **Функции активации** добавляют в сеть нелинейность («изгиб»), позволяя разделять безопасный и вредоносный код сложными границами.
* **LayerNorm (Нормализация):** Удерживает числа внутри сети в диапазоне от -3 до +3. Без нее числа при умножении матриц либо взрываются до миллиардов, либо затухают в нуль.
* **Dropout (Дропаут):** Во время тренировки мы случайно "выключаем" 20-30% случайных нейронов. Это заставляет оставшиеся нейроны не надеяться на соседей, а выучивать реальные правила (защита от зубрежки / переобучения).

### 2. 📐 Глубокая математика
1. **GELU (Gaussian Error Linear Unit):**  
   $$GELU(z) = z \cdot \Phi(z) = z \cdot P(X \le z), \quad X \sim \mathcal{N}(0, 1)$$  
   Аппроксимация для быстрых вычислений:
   $$GELU(z) \approx 0.5z \cdot \left(1 + \tanh\left(\sqrt{\frac{2}{\pi}} (z + 0.044715 z^3)\right)\right)$$
2. **Sigmoid ($\sigma$):**
   $$\sigma(z) = \frac{1}{1 + e^{-z}}, \quad \sigma'(z) = \sigma(z)(1 - \sigma(z))$$
3. **Softmax (для выбора одного из K классов уязвимостей):**
   $$Softmax(z)_i = \frac{e^{z_i}}{\sum_{j=1}^K e^{z_j}}, \quad \sum_{i=1}^K Softmax(z)_i = 1.0$$
4. **Layer Normalization:**
   $$\mu = \frac{1}{D}\sum_{i=1}^D x_i, \quad \sigma^2 = \frac{1}{D}\sum_{i=1}^D (x_i - \mu)^2, \quad \hat{x}_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \epsilon}} \cdot \gamma + \beta$$

### 3. 💻 Код на Python (PyTorch)
```python
import torch
import torch.nn as nn

class ProductionDenseBlock(nn.Module):
    def __init__(self, in_features: int, out_features: int, dropout_rate: float = 0.3):
        super().__init__()
        self.linear = nn.Linear(in_features, out_features)
        self.norm = nn.LayerNorm(out_features)
        self.activation = nn.GELU()
        self.dropout = nn.Dropout(p=dropout_rate)

    def forward(self, x):
        # 1. Линейный слой
        x = self.linear(x)
        # 2. Нормализация по слою (стабильность градиентов)
        x = self.norm(x)
        # 3. Нелинейность GELU
        x = self.activation(x)
        # 4. Регуляризация от переобучения
        x = self.dropout(x)
        return x

block = ProductionDenseBlock(in_features=12, out_features=64)
dummy_meta = torch.randn(4, 12) # Батч из 4 файлов по 12 признаков
print("Выход плотного блока:", block(dummy_meta).shape) # [4, 64]
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Сравнитель активаций".
* **Элементы:** Ползунок входного значения $z$ от -5.0 до +5.0. 
* **График:** Графики функций ReLU, GELU, Sigmoid, которые динамически подсвечивают текущую точку и её производную (градиент).

### 5. 🧪 Тест и Практика
* **Вопрос:** Почему в моделях анализа исходного кода используют LayerNorm, а не BatchNorm?  
  *Ответ:* Методы в коде имеют разную длину, а при инференсе мы часто проверяем один метод (батч = 1). BatchNorm зависит от размера батча и ломается на одиночных примерах, а LayerNorm нормализует признаки внутри самого фрагмента кода независимо от батча.

## 🟢 ШАГ 3. Векторизация кода: Токенизация и Embedding-пространство

### 1. 💡 Простыми словами
Нейросеть не читает английские буквы или ключевые слова Kotlin/Java `fun`, `class`, `SELECT`.
Мы должны превратить текст программы в векторные координаты.
1. **Токенизация (BPE — Byte Pair Encoding):** Мы делим код на кусочки. Частые слова вроде `SELECT` становятся отдельными токенами. Редкие имена переменных разбиваются на подслова: `getUserById` $\to$ `['get', 'User', 'By', 'Id']`.
2. **Словарь (Vocabulary):** Создается справочник (например, на 8192 слова). Каждому токену дается числовой идентификатор (Token ID).
3. **Эмбеддинг (Embedding Layer):** Каждый ID превращается в вектор из 128 чисел. Сеть сама обучается так, чтобы слова с похожим смыслом (`password`, `secret`, `token`) в 128-мерном пространстве находились рядом, а `print` или `int` — далеко.

### 2. 📐 Глубокая математика
1. **Матрица эмбеддингов:** $E \in \mathbb{R}^{V \times d_{emb}}$, где $V = 8192$ (размер словаря), $d_{emb} = 128$.
2. **Извлечение вектора (Look-up table):**  
   Для токена с индексом $i$:
   $$e_i = \text{OneHot}(i) \cdot E = E[i] \in \mathbb{R}^{128}$$
3. **Косинусное сходство (Cosine Similarity) между векторами токенов $A$ и $B$:**
   $$\cos(\theta) = \frac{A \cdot B}{\|A\|_2 \cdot \|B\|_2} = \frac{\sum A_i B_i}{\sqrt{\sum A_i^2} \sqrt{\sum B_i^2}}$$
   * Если $\cos(\theta) \to 1.0$ — слова семантически идентичны по смыслу уязвимости.
   * Если $\cos(\theta) \to 0.0$ — слова независимы.

### 3. 💻 Код на Python (PyTorch)
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class CodeEmbedding(nn.Module):
    def __init__(self, vocab_size=8192, emb_dim=128):
        super().__init__()
        # Индекс 0 зарезервирован под <PAD> (выравнивание длины)
        self.embedding = nn.Embedding(num_embeddings=vocab_size, embedding_dim=emb_dim, padding_idx=0)

    def forward(self, token_ids):
        # token_ids: [Batch, Sequence_Length]
        return self.embedding(token_ids)

# Пример: 2 строки кода по 4 токена
token_batch = torch.tensor([
    [15, 240, 89, 0],  # "SELECT * FROM <PAD>"
    [89, 12, 450, 99]  # "FROM users WHERE id"
])
emb = CodeEmbedding()
vectors = emb(token_batch)
print("Форма матрицы векторов (Batch, Tokens, Dim):", vectors.shape) # [2, 4, 128]
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Семантическое расстояние в коде".
* **Элементы:** Выпадающие списки двух токенов (например: `password` vs `secret`, `password` vs `println`). 
* **Вывод:** Расчет косинусного сходства и визуализация двух стрелок в 2D-проекции.

### 5. 🧪 Тест и Практика
* **Задача:** Токен $A$ имеет эмбеддинг $[1.0, 0.0]$, а токен $B$ — $[0.0, 2.0]$. Найди косинусное сходство между ними.  
  *Решение:* Скалярное произведение $A \cdot B = (1.0 \cdot 0.0) + (0.0 \cdot 2.0) = 0$. Значит $\cos(\theta) = 0$ (векторы ортогональны, токены никак не связаны).

## 🟢 ШАГ 4. Поток 1: Рекуррентные сети и Bi-LSTM (Анализ цепочек вызовов)

### 1. 💡 Простыми словами
Почему код нельзя анализировать как мешок отдельных слов? Потому что важен **порядок инструкций**!
Посмотрим на Taint Analysis (анализ заражения данных):
* **Source (Источник):** `val input = request.getParameter("id")` (грязные данные пришли от пользователя).
* **Sanitizer (Очистка):** `val safeId = input.toLong()` (превращение в число убивает SQL-инъекцию).
* **Sink (Приемник):** `database.query("... " + safeId)` (выполнение в БД).

Если читать код только слева направо, мы поймем, куда переменная течет. Но если читать справа налево (от опасной функции `database.query` назад к источнику), мы мгновенно поймем, проверялась ли эта переменная ранее.
Именно поэтому мы берем **Bi-LSTM (двунаправленную LSTM)**: она параллельно читает метод с начала в конец и с конца в начало!

### 2. 📐 Глубокая математика
LSTM спасает от затухания градиента благодаря шине долговременной памяти ($C_t$).
На каждом шаге токена $t$ ячейка вычисляет:
$$\begin{aligned}
f_t &= \sigma(W_f x_t + U_f h_{t-1} + b_f) && \text{Forget Gate: сколько старой памяти забыть (0..1)} \\
i_t &= \sigma(W_i x_t + U_i h_{t-1} + b_i) && \text{Input Gate: сколько новой информации записать} \\
\tilde{C}_t &= \tanh(W_c x_t + U_c h_{t-1} + b_c) && \text{Новый кандидат в память} \\
C_t &= f_t \odot C_{t-1} + i_t \odot \tilde{C}_t && \text{Шина памяти: аддитивное обновление без потерь} \\
o_t &= \sigma(W_o x_t + U_o h_{t-1} + b_o) && \text{Output Gate: какую часть памяти выдать наружу} \\
h_t &= o_t \odot \tanh(C_t) && \text{Текущий скрытый вектор токена}
\end{aligned}$$
При двунаправленном проходе прямой вектор $\overrightarrow{h}_t \in \mathbb{R}^{128}$ и обратный $\overleftarrow{h}_t \in \mathbb{R}^{128}$ склеиваются:
$$h_t = [\overrightarrow{h}_t \,;\, \overleftarrow{h}_t] \in \mathbb{R}^{256}$$

### 3. 💻 Код на Python (PyTorch)
```python
import torch
import torch.nn as nn

class BiLSTMCodeEncoder(nn.Module):
    def __init__(self, emb_dim=128, hidden_dim=128):
        super().__init__()
        # batch_first=True ожидает форму [Batch, Seq_Len, Emb_Dim]
        self.lstm = nn.LSTM(
            input_size=emb_dim,
            hidden_size=hidden_dim,
            num_layers=1,
            batch_first=True,
            bidirectional=True
        )

    def forward(self, embedded_tokens):
        # outputs содержит скрытые состояния всех токенов [Batch, Seq_Len, 256]
        outputs, (h_n, c_n) = self.lstm(embedded_tokens)
        return outputs

encoder = BiLSTMCodeEncoder()
dummy_code = torch.randn(2, 64, 128) # 2 метода по 64 токена
h_all = encoder(dummy_code)
print("Форма выхода Bi-LSTM:", h_all.shape) # [2, 64, 256]
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Симулятор вентилей LSTM (Forget & Input)".
* **Элементы:** Ползунок степени важности токена ($i_t$) и ползунок стирания старой памяти ($f_t$).
* **Вывод:** Динамическое изменение величины долговременной памяти $C_t$.

### 5. 🧪 Тест и Практика
* **Вопрос:** Зачем в формуле ячейки памяти $C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$ используется сложение, а не матричное умножение?  
  *Ответ:* Сложение позволяет градиентам при обратном распространении ошибки протекать через сотни временных шагов без затухания (градиент суммы равен единице).

## 🟢 ШАГ 5. Поток 1: Механизм внимания (Self-Attention Pooling)

### 1. 💡 Простыми словами
Метод в кодовой базе может состоять из 200 токенов. Если просто усреднить все векторы, сигнал об уязвимости утонет в сотнях запятых, скобок и объявлений переменных.
**Механизм внимания (Self-Attention)** работает как маркер-хайлайтер:
Сеть смотрит на всю последовательность и вычисляет коэффициент внимания $\alpha \in [0.0, 1.0]$ для каждого токена. Токены `query`, `+`, `WHERE`, `id` получают 90% всего внимания, а токены `{`, `val`, `return` — меньше 1%.
Затем сеть складывает все токены, умножая их на этот вес. Мы получаем один емкий вектор метода (256 чисел).

### 2. 📐 Глубокая математика
1. **Проекция скрытого состояния:**
   $$u_t = \tanh(W_a \cdot h_t + b_a), \quad u_t \in \mathbb{R}^{d_a} \quad (d_a = 64)$$
2. **Скалярная оценка важности (Score):**
   $$s_t = v_a^T \cdot u_t \in \mathbb{R}$$
   где $v_a$ — обучаемый контекстный вектор-шаблон идеальной уязвимости.
3. **Маскирование заполнителей (Padding Mask):**
   Если на позиции $t$ стоит токен `<PAD>`, принудительно зануляем его вес: $s_t = -\infty$.
4. **Нормализация весов (Softmax):**
   $$\alpha_t = \frac{\exp(s_t)}{\sum_{k=1}^T \exp(s_k)}, \quad \sum_{t=1}^T \alpha_t = 1.0$$
5. **Взвешенная сумма (Вектор контекста метода $c$):**
   $$c = \sum_{t=1}^T \alpha_t \cdot h_t \in \mathbb{R}^{256}$$

### 3. 💻 Код на Python (PyTorch)
```python
import torch
import torch.nn as nn

class SelfAttentionPooling(nn.Module):
    def __init__(self, in_features=256, att_dim=64):
        super().__init__()
        self.W_a = nn.Linear(in_features, att_dim)
        self.v_a = nn.Linear(att_dim, 1, bias=False)

    def forward(self, h, mask=None):
        # h: [Batch, Seq_Len, 256]
        # 1. Проекция и нелинейность
        u = torch.tanh(self.W_a(h)) # [Batch, Seq_Len, 64]
        # 2. Скалярный скор
        scores = self.v_a(u).squeeze(-1) # [Batch, Seq_Len]

        # 3. Маскирование
        if mask is not None:
            scores = scores.masked_fill(mask == 0, -1e9)

        # 4. Веса внимания через Softmax
        weights = torch.softmax(scores, dim=-1) # [Batch, Seq_Len]

        # 5. Свертка последовательности в один вектор
        context = torch.bmm(weights.unsqueeze(1), h).squeeze(1) # [Batch, 256]
        return context, weights
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Инспектор внимания к строке кода".
* **Код в виджете:** `val q = "SELECT * FROM users WHERE name = '" + userName + "'"`
* **Элементы:** Кнопка "Рассчитать внимание". Токены `SELECT`, `+`, `userName` подсвечиваются ярким красным фоном (вес 0.85), а `val`, `=` — блеклым серым (вес 0.02).

### 5. 🧪 Тест и Практика
* **Вопрос:** Зачем мы маскируем токены `<PAD>` числом $-10^9$ перед Softmax?  
  *Ответ:* Экспонента $e^{-10^9} \approx 0$. Это гарантирует, что искусственные нули выравнивания длины получат строго 0% внимания и не исказят вектор метода.

## 🟢 ШАГ 6. Поток 2: Анализ метаданных и Энтропия Шеннона

### 1. 💡 Простыми словами
У каждого файла и строки в кодовой базе есть "паспортные данные", которые видны даже без чтения кода:
* Встретилась подозрительная строка `x = "AKIAIOSFODNN7EXAMPLE"`. Это боевой ключ или тестовый мусор?
* Мы можем математически посчитать **информационный хаос (энтропию)**. Человеческие слова имеют повторяющиеся слоги $\to$ низкая энтропия. Сгенерированные криптографические ключи состоят из случайных символов $\to$ **экстремально высокая энтропия**.
* Мы упаковываем 12 таких числовых характеристик в отдельный вектор и прогоняем через второй поток нейросети.

### 2. 📐 Глубокая математика
1. **Формула информационной энтропии Шеннона:**
   $$H(S) = -\sum_{i=1}^k p_i \log_2(p_i)$$
   где $p_i = \frac{\text{кол-во символа } c_i}{\text{общая длина строки } L}$.
2. **Сравнение на реальных примерах:**
   * Строка `"aaaa"`: символ `'a'` встречается 4/4 раза ($p = 1.0$).  
     $$H(S) = -1.0 \cdot \log_2(1.0) = 0.0 \text{ бит (хаоса нет)}$$
   * Строка `"password"`: длина 8. Символы: `p:1, a:1, s:2, w:1, o:1, r:1, d:1`.  
     $$H(S) \approx 2.75 \text{ бит (обычное английское слово)}$$
   * Токен `"4f8a9b2c-e1d7-4a0f"` (высокий хаос):  
     $$H(S) \approx 3.75 - 4.2 \text{ бит (вероятный секрет!)}$$
3. **12 признаков мета-вектора ($m \in \mathbb{R}^{12}$):**  
   `[1. Энтропия, 2. Длина литерала, 3. Глубина AST, 4. Флаг '?', 5. Флаг '+', 6. Флаг @PreAuthorize, 7. Флаг permitAll, 8. Флаг TrustAllCert, 9. Флаг CORS *, 10. Роль файла (Controller/Service), 11. Расширение (.kt/.yml), 12. Вхождение 'Principal']`.
4. **Z-Score нормализация:**
   $$\hat{m}_j = \frac{m_j - \mu_j}{\sigma_j}$$

### 3. 💻 Код на Python
```python
import math
from collections import Counter
import torch
import torch.nn as nn

def shannon_entropy(s: str) -> float:
    if not s: return 0.0
    length = len(s)
    counts = Counter(s)
    return -sum((count / length) * math.log2(count / length) for count in counts.values())

class MetadataStreamMLP(nn.Module):
    def __init__(self, in_features=12, out_features=32):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_features, 64),
            nn.LayerNorm(64),
            nn.GELU(),
            nn.Dropout(0.2),
            nn.Linear(64, out_features),
            nn.LayerNorm(out_features),
            nn.GELU()
        )

    def forward(self, x):
        return self.net(x) # Выход: компактный вектор [Batch, 32]
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Живой калькулятор энтропии Шеннона".
* **Элементы:** Поле ввода текста.
* **Вывод:** График частот символов, мгновенное вычисление $H(S)$ в битах и индикатор: Зеленый ($< 3.0$ = безопасное слово), Желтый ($3.0 - 3.4$ = подозрительно), Красный ($> 3.4$ = боевой секрет!).

### 5. 🧪 Тест и Практика
* **Задача:** Посчитай вручную энтропию строки `"abab"`.  
  *Решение:* Символы `'a'` и `'b'` встречаются по 2 раза из 4. $p_a = 0.5, p_b = 0.5$.  
  $H(S) = -(0.5 \log_2(0.5) + 0.5 \log_2(0.5)) = -(0.5 \cdot (-1) + 0.5 \cdot (-1)) = -(-1.0) = 1.0$ бит.

## 🟢 ШАГ 7. Слияние потоков (Late Fusion) и Мультизадачные головы

### 1. 💡 Простыми словами
У нас готовы два независимых экспертных мнения:
1. Эксперт по синтаксису (Поток 1) подготовил вектор кода $c$ (256 чисел).
2. Эксперт по метаданным (Поток 2) подготовил вектор свойств $m_{out}$ (32 числа).

Мы объединяем их в единый вектор: **$256 + 32 = 288$ чисел**.
Затем нейросеть делает два параллельных вывода (**Multi-Task Learning**):
* **Голова 1 (Бинарный фильтр):** Отвечает на главный вопрос бизнеса: *«Это реальная уязвимость (1) или безопасный ложный шум (0)?»*
* **Голова 2 (Категоризатор CWE):** Определяет тип атаки (CWE-89 SQLi, CWE-798 Hardcoded Secret, CWE-639 IDOR, CWE-295 TLS Bypass, CWE-306 Missing Auth).

### 2. 📐 Глубокая математика
1. **Late Fusion (Поздняя конкатенация):**
   $$z_{fused} = [c \,;\, m_{out}] \in \mathbb{R}^{288}$$
2. **Проекция скрытых представлений:**
   $$z = \text{Dropout}(\text{GELU}(\text{LayerNorm}(W_{fuse} z_{fused} + b_{fuse})), p=0.3) \in \mathbb{R}^{128}$$
3. **Голова 1 — Вероятность уязвимости:**
   $$\hat{y}_{vuln} = \sigma(W_{bin} \cdot z + b_{bin}) \in [0.0, 1.0]$$
4. **Голова 2 — Логиты классов CWE:**
   $$\hat{y}_{cwe} = Softmax(W_{cwe} \cdot z + b_{cwe}) \in \mathbb{R}^6$$

### 3. 💻 Код на Python (Архитектура DualBranchAppSecNet целиком)
```python
import torch
import torch.nn as nn

class DualBranchAppSecNet(nn.Module):
    def __init__(self, vocab_size=8192, emb_dim=128, lstm_dim=128, meta_dim=12, num_classes=6):
        super().__init__()
        # 1. Поток кода
        self.embedding = nn.Embedding(vocab_size, emb_dim, padding_idx=0)
        self.lstm = nn.LSTM(emb_dim, lstm_dim, batch_first=True, bidirectional=True)
        self.att_proj = nn.Linear(lstm_dim * 2, 64)
        self.att_v = nn.Linear(64, 1, bias=False)
        
        # 2. Поток метаданных
        self.meta_stream = nn.Sequential(
            nn.Linear(meta_dim, 32),
            nn.LayerNorm(32),
            nn.GELU()
        )
        
        # 3. Блок слияния (Fusion)
        self.fuse = nn.Sequential(
            nn.Linear((lstm_dim * 2) + 32, 128),
            nn.LayerNorm(128),
            nn.GELU(),
            nn.Dropout(0.3)
        )
        
        # 4. Две головы
        self.head_vuln = nn.Linear(128, 1)          # Бинарная
        self.head_cwe = nn.Linear(128, num_classes)  # 6 классов CWE

    def forward(self, token_ids, mask, metadata):
        # Поток 1: Код
        x = self.embedding(token_ids)
        h, _ = self.lstm(x)
        scores = self.att_v(torch.tanh(self.att_proj(h))).squeeze(-1)
        scores = scores.masked_fill(mask == 0, -1e9)
        weights = torch.softmax(scores, dim=-1).unsqueeze(-1)
        code_vec = torch.sum(h * weights, dim=1) # [Batch, 256]

        # Поток 2: Метаданные
        meta_vec = self.meta_stream(metadata)   # [Batch, 32]

        # Слияние
        fused = torch.cat([code_vec, meta_vec], dim=-1) # [Batch, 288]
        z = self.fuse(fused) # [Batch, 128]

        # Предсказания
        prob_vuln = torch.sigmoid(self.head_vuln(z))
        logits_cwe = self.head_cwe(z)
        return prob_vuln, logits_cwe
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Интерактивная схема нейросети".
* **Элементы:** Наведение на блоки (Embedding, Bi-LSTM, Attention, Meta-MLP, Fusion, Heads). При наведении подсвечиваются размерности тензоров и поток данных.

### 5. 🧪 Тест и Практика
* **Вопрос:** Зачем мы обучаем две головы одновременно, если главная цель — просто найти уязвимость?  
  *Ответ:* Мультизадачное обучение (Multi-Task Learning) служит регуляризатором. Сеть вынуждена понимать физическую природу конкретного типа атаки (CWE-89 vs CWE-798), что повышает качество бинарной фильтрации ложных тревог.

## 🟢 ШАГ 8. Обучение: Борьба с дисбалансом классов (Focal Loss) и Метрики

### 1. 💡 Простыми словами
Представь экзамен, где 99 вопросов из 100 имеют правильный ответ «НЕТ», и только 1 вопрос — «ДА».
Ленивый студент просто ответит «НЕТ» на все 100 вопросов и получит оценку 99%!
В реальной кодовой базе чистый безопасный код составляет **99.5%**, а уязвимости — **0.5%**.
* Обычная функция ошибки (Binary Cross Entropy) заставляет нейросеть лениться и всегда говорить: *«Код чист!»*.
* Чтобы исправить это, мы используем **Focal Loss**: она зануляет важность очевидных безопасных строк и удесятеряет штраф за пропуск редкой уязвимости!

### 2. 📐 Глубокая математика
1. **Формула Focal Loss (Lin et al.):**
   $$\mathcal{L}_{Focal}(p_t) = -\alpha_t (1 - p_t)^\gamma \log(p_t)$$
   где:
   $$p_t = \begin{cases} \hat{y}, & \text{если } y = 1 \\ 1 - \hat{y}, & \text{если } y = 0 \end{cases}, \quad \alpha_t = \begin{cases} 0.75, & \text{если } y = 1 \\ 0.25, & \text{если } y = 0 \end{cases}$$
   * Модулирующий множитель $(1 - p_t)^\gamma$ при $\gamma = 2.0$:  
     Если сеть уверена в чистом коде ($p_t = 0.99$), множитель равен $(1 - 0.99)^2 = 0.0001$ (штраф занулен).  
     Если сеть сомневается в редкой уязвимости ($p_t = 0.2$), множитель равен $(1 - 0.2)^2 = 0.64$ (градиент максимален!).
2. **Метрики AppSec:**
   $$\text{Precision} = \frac{TP}{TP + FP} \quad \text{(Точность: доля реальных дыр среди всех алертов)}$$
   $$\text{Recall} = \frac{TP}{TP + FN} \quad \text{(Полнота: доля найденных дыр от всех существующих)}$$
   $$F_{\beta=2} = 5 \cdot \frac{\text{Precision} \cdot \text{Recall}}{4 \cdot \text{Precision} + \text{Recall}} \quad \text{(Приоритет полноте: пропуск уязвимости опаснее ложной тревоги!)}$$

### 3. 💻 Код на Python
```python
import torch
import torch.nn as nn

class BinaryFocalLoss(nn.Module):
    def __init__(self, alpha=0.75, gamma=2.0):
        super().__init__()
        self.alpha = alpha
        self.gamma = gamma

    def forward(self, p, targets):
        # p: предсказанные вероятности [Batch, 1], targets: метки 0 или 1
        p_t = p * targets + (1 - p) * (1 - targets)
        alpha_t = self.alpha * targets + (1 - self.alpha) * (1 - targets)
        loss = -alpha_t * torch.pow((1 - p_t), self.gamma) * torch.log(p_t + 1e-8)
        return loss.mean()
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Focal Loss против стандартной Cross-Entropy".
* **Элементы:** Ползунок вероятности $p_t$ от 0.01 до 0.99 и ползунок фактора $\gamma$ от 0 до 5.
* **График:** Сравнение кривой ошибки BCE и кривой Focal Loss. Наглядно видно, как при $p_t > 0.6$ ошибка Focal Loss падает до нуля.

### 5. 🧪 Тест и Практика
* **Вопрос:** Сканер нашел 10 уязвимостей. 8 из них оказались настоящими, а 2 — ложными срабатываниями на тестах. Найди Precision.  
  *Решение:* $TP = 8, FP = 2$. $\text{Precision} = \frac{8}{8 + 2} = \frac{8}{10} = 80\%$.

## 🟢 ШАГ 9. Экспорт в ONNX и INT8 Квантование (Сжатие до 15 МБ)

### 1. 💡 Простыми словами
Обученная модель на PyTorch сохраняется в файл `.pt` размером 70–100 МБ.
Для её запуска требуется установить Python, PyTorch, CUDA и кучу зависимостей на 3 ГБ диска. Это медленно и непригодно для микросервиса.
Что мы делаем:
1. **Экспорт в ONNX:** Превращаем модель в статичный граф вычислений на C++ без зависимости от Python.
2. **Квантование INT8:** Каждое 32-битное число с плавающей точкой (FP32) мы сжимаем в 8-битное целое число (INT8).  
Модель уменьшается в **4 раза** (до **~14.8 МБ**), а скорость на процессоре подскакивает в 3–5 раз благодаря инструкциям **AVX-512 VNNI**!

### 2. 📐 Глубокая математика
1. **Аффинное квантование FP32 $\to$ INT8:**
   $$q = \text{round}\left(\frac{x}{S}\right) + Z$$
   * $S$ (Scale): Масштабный коэффициент:
     $$S = \frac{x_{max} - x_{min}}{255}$$
   * $Z$ (Zero-Point): Смещение нуля в диапазон целых чисел $[-128, 127]$.
2. **Обратное де-квантование:**
   $$\hat{x} = S \cdot (q - Z)$$
   Вместо медленного умножения чисел с запятой процессор выполняет целочисленные операции над `int8` за один такт!

### 3. 💻 Код на Python (Скрипт компиляции и сжатия)
```python
import torch
from onnxruntime.quantization import quantize_dynamic, QuantType

def export_and_quantize(model, onnx_fp32_path="model.onnx", onnx_int8_path="model_int8.onnx"):
    model.eval()
    # Создаем фиктивные входы для трассировки графа
    dummy_tokens = torch.randint(0, 1000, (1, 256), dtype=torch.int64)
    dummy_mask = torch.ones((1, 256), dtype=torch.int64)
    dummy_meta = torch.randn((1, 12), dtype=torch.float32)

    # 1. Экспорт в ONNX с динамическими размерами (любая длина метода!)
    torch.onnx.export(
        model,
        (dummy_tokens, dummy_mask, dummy_meta),
        onnx_fp32_path,
        input_names=['token_ids', 'mask', 'metadata'],
        output_names=['prob_vuln', 'logits_cwe'],
        dynamic_axes={
            'token_ids': {0: 'batch', 1: 'seq_len'},
            'mask': {0: 'batch', 1: 'seq_len'},
            'metadata': {0: 'batch'}
        },
        opset_version=14
    )
    print("✅ Успешно экспортировано в FP32 ONNX!")

    # 2. Квантование до 8 бит
    quantize_dynamic(
        model_input=onnx_fp32_path,
        model_output=onnx_int8_path,
        weight_type=QuantType.QInt8
    )
    print(f"🚀 Модель сжата до INT8: {onnx_int8_path}")
```

### 4. 🎮 Интерактивная песочница
* **Виджет:** "Калькулятор INT8 квантования".
* **Элементы:** Поле ввода вещественного числа (например, 3.14159) и диапазон $[x_{min}, x_{max}]$.
* **Вывод:** Мгновенный расчет шага квантования $S$, целочисленного байта $q \in [-128, 127]$ и погрешности восстановления $|x - \hat{x}|$.

### 5. 🧪 Тест и Практика
* **Вопрос:** Сколько байт памяти экономится на 1 миллионе параметров при переходе с FP32 на INT8?  
  *Ответ:* В FP32 1 млн параметров занимает $4 \text{ МБ}$ ($1\,000\,000 \cdot 4$ байта). В INT8 — ровно $1 \text{ МБ}$ ($1\,000\,000 \cdot 1$ байт). Экономия: ровно $3 \text{ МБ}$ (в 4 раза).

```typescript
export interface ScanPrediction {
  isVulnerable: boolean;
  confidence: number;
  verdict: 'BLOCKED' | 'SUSPICIOUS' | 'CLEAN';
}

export class NeuralClassifierService {
  private session: ort.InferenceSession | null = null;

  async initialize(modelPath: string = 'backend/models/appsec_classifier.onnx'): Promise<void> {
    // Загружаем скомпилированную C++ сессию ONNX
    this.session = await ort.InferenceSession.create(modelPath);
    console.log('🛡️ [uncflow] Нейросетевой фильтр успешно инициализирован в памяти');
  }

  async evaluateSnippet(
    tokenIds: number[],
    metadata12: number[]
  ): Promise<ScanPrediction> {
    if (!this.session) throw new Error('Сессия ONNX не готова!');

    const seqLen = tokenIds.length;
    // Готовим тензоры
    const tokenTensor = new ort.Tensor('int64', BigInt64Array.from(tokenIds.map(BigInt)), [1, seqLen]);
    const maskTensor = new ort.Tensor('int64', new BigInt64Array(seqLen).fill(1n), [1, seqLen]);
    const metaTensor = new ort.Tensor('float32', Float32Array.from(metadata12), [1, 12]);

    // Выполняем инференс
    const feeds = {
      token_ids: tokenTensor,
      mask: maskTensor,
      metadata: metaTensor
    };
    const outputs = await this.session.run(feeds);
    
    // Считываем вероятность бинарной головы
    const vulnProb = (outputs.prob_vuln.data as Float32Array)[0];

    let verdict: 'BLOCKED' | 'SUSPICIOUS' | 'CLEAN' = 'CLEAN';
    if (vulnProb >= 0.85) verdict = 'BLOCKED';
    else if (vulnProb >= 0.40) verdict = 'SUSPICIOUS';

    return {
      isVulnerable: vulnProb >= 0.85,
      confidence: Math.round(vulnProb * 1000) / 1000,
      verdict
    };
  }
}
```

* **Вопрос:** Почему мы делим решения на 3 зоны (Чисто, Экспертиза, Блокировка), а не просто 50/50?  
  *Ответ:* В кибербезопасности цена ошибки несимметрична. Пограничные случаи ($0.40 - 0.85$) безопаснее передать внешнему эксперту или LLM (GigaChat), гарантируя 100% отсутствие пропусков атак (Zero False Negatives).
